# خطة مستقبلية للمقالات والنشر الاجتماعي

الحالة: مؤجلة. هذه الخطة تحفظ القرارات والأسئلة اللازمة عندما تصبح المبادرة أولوية. تنفيذ إعادة تصميم الموقع لا يعتمد عليها.

## الهدف

إعداد مقالات عربية أصلية من مصادر معتمدة، ونشرها في موقع هلا كوميرس، ثم إعداد منشورات مناسبة لقنوات التواصل الاجتماعي مع تتبع الحالة والنتائج.

## ما ثبت من المستودع الحالي

- الواجهة الحالية React + Vite، والمدونة تعرض محتوى معرفًا داخل `artifacts/hala-landing/src/data/blogPosts.ts`.
- لا توجد في واجهة الموقع الحالية لوحة تحرير للمقالات أو خدمة نشر خلفية.
- اختيار نظام إدارة المحتوى جزء من قرار بنية الموقع الجديد، ولذلك تُصمم الأتمتة حول واجهة نشر مستقرة، ولا تُربط مباشرة بملف TypeScript.

## تدفق العمل المقترح

1. **اختيار المصادر:** قائمة RSS أو APIs أو روابط معتمدة، مع تسجيل المصدر ورابطه وتاريخ جلبه وحق استخدامه.
2. **الفرز ومنع التكرار:** استبعاد المواد البعيدة عن تجارة الخليج والخدمات التشغيلية، وتطبيع الرابط والتحقق من التكرار.
3. **صياغة المسودة:** استخراج الأفكار والتحقق من الوقائع، ثم كتابة مقال عربي أصلي مع عنوان وملخص وتصنيف وروابط إسناد وصورة مرخصة أو أصلية.
4. **المراجعة التحريرية:** تدقيق اللغة والوقائع والأرقام والحقوق ونبرة هلا. تُحفظ نتيجة المراجعة واسم المسؤول.
5. **النشر في الموقع:** إنشاء مسودة عبر CMS معتمد، ثم النشر أو الجدولة بعد الموافقة، وتسجيل معرف المقال ورابطه النهائي.
6. **إعداد المنشورات الاجتماعية:** كتابة نسخة مستقلة لكل قناة، مع الصورة والرابط ووسوم التتبع المناسبة.
7. **الموافقة والجدولة:** مراجعة النسخ الاجتماعية قبل إرسالها عبر واجهات القنوات الرسمية أو أداة جدولة معتمدة.
8. **المتابعة:** حفظ معرف كل منشور وحالته، وإعادة المحاولة للأخطاء المؤقتة، والتنبيه عند فشل النشر أو انتهاء صلاحية الربط.

## قرارات البنية عند التفعيل

- إذا أصبح WordPress نظام المحتوى، تُستخدم مسوداته وصلاحياته وREST API بمفتاح تطبيق محدود الصلاحية.
- إذا بقيت واجهة React أو انتقلت إلى Next.js، يُختار CMS مستقل قبل بناء التدفق. واجهة الموقع تقرأ المحتوى من CMS ولا تكون هي مخزن المقالات.
- تحفظ بيانات اعتماد الخدمات خارج المستودع، مع صلاحيات محدودة لكل قناة وسجل لتدوير المفاتيح.
- يبدأ الإصدار الأول بموافقة بشرية قبل نشر المقالات والمنشورات. يُعاد تقييم النشر الآلي الكامل بعد قياس الجودة.

## بيانات كل مادة

المصدر، الرابط الأصلي، حالة حق الاستخدام، الموضوع، التصنيف، حالة المسودة، إصدارات النص، المحرر، وقت الاعتماد، معرف المقال، رابطه النهائي، نسخ القنوات، معرفات المنشورات، حالات النشر، سجل الأخطاء والمحاولات.

## أول إصدار عند بدء التنفيذ

مصدران أو ثلاثة مصادر معتمدة، مسودة عربية للمراجعة، نشر على الموقع بعد الاعتماد، وقناة اجتماعية واحدة. ثم تُقاس دقة المحتوى، ووقت المراجعة، والتكرار، ونسبة إخفاق النشر قبل التوسع.

## معلومات يجب حسمها وقت التنفيذ

- نظام إدارة المحتوى النهائي واستضافة خدمة الأتمتة.
- المصادر المسموح استخدامها وسياسة الإسناد والصور.
- القنوات الاجتماعية المطلوبة وصلاحيات حساباتها وقيود APIs.
- صاحب الموافقة التحريرية، حجم المحتوى الشهري، ونبرة الكتابة.
- حدود التكلفة، التنبيهات، ومقاييس النجاح.
